问题发现

作为一名工业设计/人因工程研究者，我的日常文献调研流程是：

❌ 原本的工作流

  • 手动打开 PubMed、Google Scholar、Crossref 切换搜索
  • 中文提问要自己翻译成英文关键词
  • 逐篇打开 PDF 读摘要、判断相关性
  • 手动翻译英文摘要并提炼要点
  • 搜索 20 篇论文 → 产出 5 篇精炼 → 耗时 40-60 分钟

✅ 重构后的工作流

  • 终端输入一行中文研究问题
  • 系统自动翻译关键词，并行搜索 5 个学术数据库
  • AI 自动去重、评估相关性、保留前 8 篇
  • 自动翻译摘要、提取 3-5 条核心要点
  • 搜索 23 篇论文 → 产出 8 篇精炼 JSON → 耗时 40 秒

关键设计决策

为什么拆成 3 个 Agent？

单 Agent Prompt 要求"翻译 + 筛选 + 提炼"时输出不稳定。拆分后每个 Prompt 职责单一，两次运行判断一致。

为什么用结构化通信？

Agent 之间传 JSON 而非自然语言。避免理解偏差和错误累积，确保筛选 Agent 的评分能被提炼 Agent 精确读取。

中文→英文搜索优化

发现中文直接发给英文学术引擎搜不到相关论文。在 Search Agent 中加入自动翻译节点，中文提问自动转英文关键词。

中英跨语言知识库

本地 830+ 篇 PDF 以英文为主，用户用中文提问。通过 BGE-M3 多语言 Embedding 模型实现同一语义空间内的跨语言检索。
